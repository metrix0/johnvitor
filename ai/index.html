AI reporting protocol

This is the reporting endpoint for John Vitor's private Task Spotlight inbox. It receives a short final status from normal ChatGPT conversations and scheduled task/cron runs. Only report after the actual work and validation are finished.

Instructions for AI agents

1. Read the private reporting key from the key query parameter of the URL you were sent (/ai?key=...). If no key is present, explain that you cannot report; do not invent a key.

2. Determine the conversation kind. Use chat for ordinary conversations, or cron for a scheduled/recurring ChatGPT task run.

3. Determine the actual outcome. Use done only when everything requested is finished and validated; blocked if incomplete, failed, unverified, or awaiting approval; unknown only when the result cannot be established. Include a concise truthful title and summary.

4. Submit a report to https://johnvitor.com/api/ai?action=report. Preferred method: POST JSON with the header X-Report-Key: <key>. Example JSON body:

{
  "kind": "chat",
  "status": "blocked",
  "title": "Project implementation",
  "summary": "One validation step is still pending.",
  "nonce": "unique-run-id-12345678",
  "conversationUrl": ""
}

Recommended for ChatGPT with TinyFish connected: use TinyFish.fetch_content (URL fetch, not the paid browser automation) with one complete HTTPS report URL. For example, request https://johnvitor.com/api/ai?action=report&key=<key>&kind=cron&status=done&title=Example&summary=Completed&nonce=unique-run-id-12345678. Set kind=chat for a normal conversation. URL-encode the title, summary, and any supplied conversation URL; generate a new unique nonce for each new result and reuse it only when retrying. This GET fallback exists specifically for agents with read-only URL-fetch tools. Prefer POST when an approved HTTP POST tool is available.

Never mistake a fetched instruction page for submission. You must fetch the actual ?action=report URL and inspect the returned JSON. The API must confirm ok: true and a report ID. Never invent a conversation URL, claim a task was completed without validation, or disclose the private report key in your answer. TinyFish may not be available to every scheduled task, so do not promise delivery without verifying the result.

5. Verify the actual response. Successful reporting returns HTTP 200/201 with JSON {"ok":true}. If the request did not succeed, say the report was not delivered. Never claim delivery merely because an instruction was read. Report the result once per completed run, not for every intermediate message.

Important: not every AI configuration has HTTP tools. Reading this page does not guarantee the agent can send the request. Reporting keys grant write-only access. Never publish or include the key in your final user-visible answer.
